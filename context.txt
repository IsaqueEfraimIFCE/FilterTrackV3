Current Android UI behavior
---------------------------
- Initial page automatically starts BLE scanning.
- On the connect screen, scanning stays active and restarts automatically until
  the user taps "Parar"; "Retomar busca" resumes scanning.
- Auto-connect chooses the first eligible discovered device in scan order unless
  more than one `FilterTrackV3` BLE sensor is visible.
- A device is eligible if its name starts with "filtertrack" or its address was
  previously connected successfully.
- Device search shows a blue "Escolha esse" tag beside eligible FilterTrack/known
  devices while they are visible in the scan list.
- If multiple `FilterTrackV3` sensors are visible, auto-connect is paused, the
  "Escolha esse" tag is hidden, and the user must tap the intended sensor.
- Device MAC address is hidden in the Android UI when the advertised device name
  is `FilterTrackV3`.
- On every normal new connection, the app opens the filter picker.
- After a sensor restart, automatic reconnection keeps the current selected filter
  and does not open the filter picker.
- If phone Bluetooth is turned off while connected, native Android forces the BLE
  state to disconnected so the WebView does not stay frozen and the recovery
  dialog is shown.
- On unexpected connection loss, the app keeps the active local session open for
  automatic reconnect only when the latest displayed velocity is above 0.1 m/min.
  Otherwise it saves the old session and lets the next connection start a new one.
- The picker suggests the last selected filter as "Ultimo usado" and still allows
  scrolling/searching the full filter list.
- The automatic filter picker is only shown while the Monitor tab is active; the
  Sessoes, Filtros, Ajustes, and Dados navigation remains usable after connection.
- Header uses app/src/main/assets/logo_cagece.png.
- Removed startup copy "ETAPA 01" and "O sensor FilterTrack expoe o servico BLE".
- Monitor view hides raw distance. It shows:
  - velocidade de subida, m/min, 2 decimals;
  - vazao, default L/min with 1 decimal;
  - tapping vazao toggles between L/min and m3/h;
  - velocidade de subida display/chart refreshes every 10 seconds;
  - while waiting the first 10 s, both velocidade and vazao show a collecting-data
    countdown with a loading spinner;
  - when velocidade de subida is unavailable, vazao is unavailable too and both
    tiles show the current reason;
  - chart plots velocidade de subida, not distance.
- Sensor readings below 25 cm are ignored in the Android WebView pipeline.
- Water movement under 0.1 cm over the 10 s analysis window is ignored.
- Computed water velocity above 10 m/min is treated as invalid to avoid absurd
  spike values from sensor noise/outliers.
- Flow color convention in Android:
  - Subindo: success/green
  - Descendo: danger/red
- The selected-filter card does not display the raw filter name. It shows derived
  filter number, direction, location, business unit, and area. It no longer shows
  the raw id or repeats the ETA/station name inside the card.
- Vazao and velocidade de subida metric values use matching rows so the numbers
  align visually side by side.
- Settings view has BLE sensor commands based on the firmware:
  - 0: restart ESP32-C3
  - 1: enable low-power mode
  - 2: disable low-power mode / normal reading
- Settings view has a persisted debug mode toggle. When enabled it shows distance
  from the ESP, post-processed distance, velocity, 10 s flow, movement, a distance
  chart, recent raw ESP payloads, and the processing rules used by the app.
- Low-power and restart commands require confirmation through the app's own modal,
  not browser window.confirm, so WebView/file-origin text is not shown.
- Low-power force-finalizes/saves the active local session before sending command 1,
  even if the session has no samples yet.
- Restart force-finalizes/saves any active session, sends command 0, keeps scanning,
  and tries to reconnect automatically without reloading the WebView.
- Unexpected Bluetooth stop or device disconnection opens a modal warning with
  options to try a sensor restart, wait for reconnection, or restart the app.

Firmware command source
-----------------------
- Current in-repo ESP-IDF firmware source:
  firmware/main/FilterTrackv3.c
- Related firmware context:
  firmware/CMakeLists.txt, firmware/main/CMakeLists.txt,
  firmware/main/idf_component.yml, firmware/dependencies.lock, firmware/sdkconfig.
- Treat firmware/build/ as generated output and firmware/managed_components/ as
  dependency/vendor code unless a task specifically targets them.
- Older notes referenced external desktop copies under FilterTrackv3espc6 and
  FilterTrackv3espc3; the in-repo source is the current implementation authority.
- tratar_comando_bluetooth:
  - case 0: esp_restart()
  - case 1: set_low_power_mode(true)
  - case 2: set_low_power_mode(false)
- Firmware reads/notifies every 100 ms in normal mode.
- Current payloads include distance plus optional raw LSM303DLHC values:
  DIST=%.2f;ACC_RAW=%d,%d,%d;MAG_RAW=%d,%d,%d
- Error/fallback payloads can include DIST=%.2f;RAW=ERRO,
  DIST=ERRO;ACC_RAW=...;MAG_RAW=..., DIST=ERRO;RAW=ERRO, and ERRO_TIMEOUT.
- BLE notification splitting can send compact D=, A=, M=, or RAW=ERRO chunks.
- Low-power mode powers down the ultrasonic sensor through GPIO10 and keeps BLE active.
- Current firmware pins: trigger GPIO20, echo GPIO21, sensor power GPIO10,
  LSM303 SDA GPIO8, LSM303 SCL GPIO9, red LED GPIO3, green LED GPIO4,
  yellow LED GPIO2.

Backend architecture
--------------------
- Single Fly Machine, single SQLite DB on one Fly volume.
- Fly volume is not replicated. Backups are the user's responsibility.
- SQLite settings:
  - foreign_keys=ON
  - busy_timeout=5000
  - WAL
  - synchronous=NORMAL
- Postgres was intentionally removed. psycopg was removed.
- SQLAlchemy models use plain JSON.
- SQLite-on-volume is the low-cost path for one backend instance with modest writes.
- Move to Postgres only when needing multiple writers, HA/failover, managed backups,
  or multi-machine scale-out.

Compact sample format
---------------------
- Backend accepts legacy list samples and compact samples.
- Legacy samples are converted to compact before storage.
- Compact shape:
  samples = {
    format: "distance_cm_x100_v1",
    t0: <first ts in ms>,
    dtUnit: "ms",
    distanceUnit: "cm",
    scale: 100,
    t: [offsetMs, ...],
    d: [distanceCm * 100, ...]
  }
- Example: d=2428 means 24.28 cm.
- About 6000 samples: ~71 KB compact vs ~240 KB object-per-sample.
- Live flow/direction UI is computed in memory and never persisted.

Velocidade de Subida and Vazão Display Changes (2026-05-07)
-------------------------------------------------------------
- Modified app/src/main/assets/index.html to accumulate chart data from 0 to current point
- Previous behavior: Chart showed only recent data limited to MAX_HISTORY_POINTS (3600)
- New behavior: Chart accumulates ALL data from session start until flow inversion
- Flow inversion detection:
  * Compares velocity sign (Math.sign(velocityMpm)) between consecutive 10-second windows
  * When velocity sign flips (e.g., from negative to positive flow), inversion triggered
  * On inversion: History resets to single point, counts down 10 seconds, then resumes accumulation
  * Example: Window 1 distance 30cm→40cm (negative velocity), Window 2 distance 40cm→30cm
    (positive velocity) = inversion detected
- Implementation: Added lastWindowVelocitySignRef to track previous window's velocity sign
- Code location: Main tick() function around line 1901-1920
- Build deployed to device: 2026-05-07 at 30 seconds build time
